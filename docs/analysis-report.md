# 2024 年 1 月纽约 Yellow Taxi 样本分析

本报告分析本项目教学清洗规则下的有效行程，回答每日与小时分布、工作日和周末差异、支付额与行程特征问题。结论基于已有 PostgreSQL 汇总，核验日期为 2026-11-01（香港时间）。后续完整 ETL 重跑与六次正式性能实验已完成，结果见 `performance-report.md`。

## 数据与方法

来源为 NYC TLC 2024 年 1 月 Yellow Taxi Parquet。原始文件 49,961,641 字节，包含 2,964,624 行；按 `src/transform.py` 的月份、非空、距离、支付额和时长规则保留 2,859,451 行，筛除 105,173 行。有效比例约 96.45%，筛除比例约 3.55%。

统计以美国纽约时间的上车时间归属日期与小时。距离单位为英里、时长为分钟、金额为美元。规则详情和数据链接见根目录 README。现有逻辑不去重，不按规则分别记录筛除数；不应把筛除数等同于错误记录数。

初次核验时的数据库成功记录：`2026-10-31 17:37:34.448644+00`，对应香港时间 `2026-11-01 01:37:34.448644`。初次核验的两次成功运行对应同一个月，同月汇总覆盖而执行记录追加，不能累计两次运行的有效行数。

## 核心指标

| 指标 | 值 |
| --- | ---: |
| 有效订单 | 2,859,451 |
| 总支付额 | $78,023,020.01 |
| 加权平均距离 | 3.3015 英里 |
| 加权平均时长 | 15.0113 分钟 |
| 日汇总行数 | 31 |
| 小时汇总行数 | 24 |

平均距离和时长采用 `SUM(每日均值 * 每日订单数) / SUM(每日订单数)`；支付额为有效样本 `total_amount` 总和，不代表利润，也不代表所有出租车业务收入。

## 分布与解释

订单最多的日期是 1 月 27 日（106,843），随后为 1 月 25 日（106,696）和 1 月 18 日（106,684）。订单最少的是 1 月 7 日（64,852），其次为 1 月 2 日（72,627）和 1 月 15 日（74,476）。这描述样本中的日分布；目前未引入天气、节假日或活动资料，不能据此解释波动原因。

按上车小时聚合整个一月，18 时最高（205,774），随后是 17 时（199,622）和 16 时（184,182）。这些是整月同一小时段的合计，并非单日高峰订单量；当前只能说明筛选样本在这些时段更集中。

工作日共 23 天，日均 92,539.61 条；周末共 8 天，日均 91,380 条。工作日日均约高 1.27%。比较使用各组的日均值，避免工作日天数更多带来的总量误导。这里按周几分类，没有单独划分公共假日，也未进行显著性检验，不能外推为长期规律。

## 一致性与页面验证

核验 `sql/verify.sql`：日汇总与小时汇总订单数均为 2,859,451，等于最新执行记录的 `clean_rows`；2,964,624 = 2,859,451 + 105,173。支付额的日、小时汇总也通过脚本对账（以核验执行输出为准）。

初次核验时在本机运行 `docker compose run --rm etl python -m pytest -q`，结果 `2 passed in 9.96s`。已有 Parquet 目录含 `_SUCCESS` 和两个非空数据分片；本次没有重新逐行扫描明细，因此该标记不单独证明明细与数据库逐行一致。

Streamlit AppTest 从运行中的看板容器加载 `/app/app.py`，四项指标为 `2,859,451`、`$78,023,020.01`、`3.30 英里`、`15.01 分钟`，无 exception 或 error 元素。Windows 端 `/_stcore/health` 返回 HTTP 200、`ok`。后续浏览器验收已显示图表与质量统计，并成功下载 31 行 CSV；下载合计订单数和支付额与数据库一致。真实截图位于 `docs/screenshots/`。

## 局限及后续

单月、单一车型及教学阈值限制了结论范围。尚未分析区域、清洗规则的独立影响或多月季节性；已记录 2 线程与 4 线程各三次端到端耗时，均值分别为 16.338 秒与 14.908 秒；本轮差异约 8.75%，仅适用于本机实验条件。不能声称已经完成分布式扩容、性能提升百分比或生产部署。

已补真实截图、SQL 原始输出、停服恢复实验和性能记录，并配置 GitHub Actions。发布与远程验证状态见 `docs/project-audit.md`。
